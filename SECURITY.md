# Security Policy

## Supported versions

The repositories here are open source test apps. Security fixes go into each repository's default
branch only. There are no maintained releases, so to pick up a fix, build from the default branch.

## Reporting a vulnerability

Please do not open a public issue for a security problem.

Report it privately through GitHub instead: go to the repository's **Security** tab and click
**Report a vulnerability**. Only the maintainers can see the report.

A useful report includes:

- the repository and the commit that is affected
- the device, OS version and steps that trigger the problem
- what happens, and what you expected to happen
- the impact as you understand it, for example a key or credential reachable by an app that should
  not have it

## What to expect

Responses are best effort. You should get an acknowledgement within a week.

If the report is accepted, the fix is prepared privately and released together with a GitHub security
advisory, and a CVE is requested when one is warranted. You will be credited in the advisory unless
you ask not to be.

If the report is declined, you will get an explanation of why, and you are free to discuss it
publicly after that.
